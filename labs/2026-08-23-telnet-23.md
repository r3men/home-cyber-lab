# Telnet Misconfiguration — Port 23

**Date:** 2026-08-23
**Status:** Complete

## Objective
Demonstrate the risks of running Telnet (port 23) on a networked system by connecting to Metasploitable2 using default credentials, and explain why this represents a misconfiguration vulnerability rather than a software exploit.

## Environment
- Attacker: Kali Linux (192.168.56.102)
- Target: Metasploitable2 (192.168.56.101)

## Tools Used
- telnet

## What is Telnet?
Telnet is a network protocol that allows users to remotely log into a machine on local area networks or the Internet. Local computers utilize a Telnet Client Program while the remote machine hosts a Telnet Server Program. Telnet has been deemed insecure due to security concerns surrounding its unencrypted handling of user credentials, allowing attackers with packet sniffers to easily extract usernames and passwords.

## Steps Taken
1. Connected to the Telnet host:
```bash
   telnet 192.168.56.101
```
2. Entered default credentials:
```bash
   metasploitable login: msfadmin
   Password: msfadmin
```

## Findings

**Finding 1: Insecure Protocol in Use**
- Severity: Critical
- Description: Telnet transmits all data including credentials in plaintext. 
  Any attacker on the same network segment running a packet sniffer could 
  capture login credentials without the user's knowledge.
- Remediation: Disable Telnet (port 23) and enforce SSH (port 22) for all 
  remote access.

**Finding 2: Default Credentials Unchanged**
- Severity: Critical
- Description: Metasploitable2 was accessible using unchanged default credentials 
  (msfadmin/msfadmin), requiring no brute force or credential cracking to gain 
  remote access.
- Remediation: Enforce a credential hardening policy requiring all default 
  credentials to be changed upon deployment.

## Takeaways
- This vulnerability is a misconfiguration, not a software exploit. There was no CVE or patch needed, just proper configuration and policy enforcement.
- In a real SOC/GRC context, both findings would be flagged as "Critical" and escalated immediately due to high severity
- Defense in depth matters, because even if Telnet were required, strong unique credentials would reduce the risk significantly.
- While credential hardening reduces the risk of direct brute force attacks, it does not mitigate the fundamental risk of Telnet credential exposure via packet sniffing. The only complete remediation is disabling Telnet and replacing it with SSH.
