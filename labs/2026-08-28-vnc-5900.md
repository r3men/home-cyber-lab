# VNC Exploitation — Port 5900

**Date:** 2026-08-28
**Status:** Complete

## Objective
Exploit the weak default password on the VNC service (port 5900) to gain unauthorized graphical desktop access to Metasploitable2 as root, and explain the risks of exposing remote desktop services with poor authentication.

## Environment
- Attacker: Kali Linux (192.168.56.102)
- Target: Metasploitable2 (192.168.56.101)

## Tools Used
- xtightvncviewer

## What is VNC?
VNC is an acronym which stands for Virtual Network Computing, essentially allowing users to remotely control other computers (similar to Telnet) with an addition of a graphical interface of the remote desktop.

## Steps Taken
1. Install xtightvncviewer:
```bash
   sudo apt install xtightvncviewer
```
2. From the Kali VirtualBox window (not SSH), connect to the VNC service (This is because the graphical display requires a display server to function properly):
```bash
   vncviewer 192.168.56.101
```
3. Enter the default password when prompted by the VNC client:
   - Password: `password`
4. Verified root access:
```bash
   whoami   # root
   id       # uid=0(root) gid=0(root) groups=0(root)
   hostname # metasploitable
```

## Findings

**Finding 1: Weak Default Password**
- Severity: Critical
- Description: The VNC service on port 5900 was protected by the trivially weak 
  password "password", requiring no brute force or credential cracking to gain access.
- Remediation: Enforce strong unique passwords for all remote access services. 
  Disable VNC if not required.

**Finding 2: Root-level Graphical Access**
- Severity: Critical
- Description: Upon connecting, full graphical desktop access was granted as root, 
  giving complete control over the target machine including file system, processes, 
  and network configuration.
- Remediation: VNC sessions should never run as root. Use a least-privilege account 
  for remote desktop access to prevent attack escalation.

**Finding 3: Unencrypted Protocol**
- Severity: High
- Description: VNC 3.3 transmits all data including the password and screen content 
  in plaintext. An attacker on the same network segment could intercept credentials 
  and session data via packet sniffing tools like Wireshark.
- Remediation: Use encrypted remote desktop alternatives such as SSH tunneling with 
  VNC, or replace with a modern encrypted protocol.

## Takeaways
- VNC is dangerous when exposed without encryption or strong authentication — 
  similar to Telnet, it was designed in an era before security was a primary concern
- Root-level remote desktop access represents total system compromise — an attacker 
  has the same access as a physical user sitting at the machine
- This is another misconfiguration vulnerability, not a software exploit — 
  the fix is policy and configuration, not patching
- In a SOC context, an open VNC port discovered during a network scan would 
  be an immediate Critical finding requiring escalation
